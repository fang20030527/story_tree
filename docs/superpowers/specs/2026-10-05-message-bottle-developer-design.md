# 留言瓶开发者模式设计

用户于 2026-10-05 确认账号授权方案，允许继续实现审核和开发者回复。

## 行为与权限

- 登录已授权的注册账号后，留言瓶显示「开发者模式」入口，进入后可切换待审核、被举报、已隐藏、全部留言；支持分页、刷新、通过、隐藏、删除、禁言和解除禁言。
- Worker secret `DEVELOPER_USER_IDS` 存储以英文逗号分隔的账号 UUID；每个开发者请求都用正常安装令牌认证，再核对账号 ID、注册状态和注销状态。未配置时没有开发者。授权绑定不可变的账号 ID，不按用户名或客户端提交的邮箱判断。
- 使用邮箱查询现有账号 ID 后由维护者配置 secret；账号注销后再以相同邮箱注册不会继承权限。现有 `ADMIN_TOKEN` 网页独立保留。
- 每条留言保留一条官方回复，最多 1,000 字。开发者可新增、修改、删除，用户看到「开发者回复」和时间。此版不开放用户互相回复。
- 回复的可见范围跟随原留言：公开留言的回复公开；待审或隐藏留言及其回复仅作者和开发者可见；屏蔽或举报后原留言与回复一起从该用户列表消失。
- 回复不自动通过审核。用户可先通过再回复，也可在待审状态回复。删除原留言、原作者注销或回复者注销会级联删除回复。
- 发布失败保留回复草稿；操作中禁止重复提交；切换账号、离开页面后丢弃旧请求结果和审核数据。权限被撤销后返回普通模式。

## 接口与数据

- 共享严格 Zod 契约集中在 `packages/contracts/src/index.ts`。
- 新增 `/v1/developer/access` 能力接口和 `/v1/developer/message-bottles` 分页审核接口，审核动作和禁言复用现有规则。
- `/v1/developer/message-bottles/:id/reply` 使用 PUT 保存唯一回复，DELETE 删除；重复相同 PUT 不改变时间，重复 DELETE 安全返回成功。
- 普通留言列表和创建请求增加显式 `includeReply=1` 参数；仅请求该扩展的新客户端收到 `reply`，同时包含 `status`。旧的基础响应、`includeStatus=1` 响应和 profile 均保持原样。
- D1 增量迁移 `0013_message_bottle_replies.sql` 创建回复表，主键为留言 ID，回复作者引用 `users(id) ON DELETE CASCADE`。
- 线上由 Worker + D1 处理，Render 兼容代理继续透传 `/v1/*`。旧 Fastify 独立数据库不增加第二套审核系统；本功能以 Worker 为开发和验证目标。
- 新接口仅返回必要的公开内容与审核信息；公开响应不暴露邮箱、账号 ID、权限配置或举报详情。审核入口不携带后台口令。

## 页面与验证

沿用现有 Expo SDK 57 主题、卡片和按钮，适配 iOS、Android、Web。删除留言、删除回复、禁言通过 `confirmAction` 确认。审核筛选提供加载、空列表、错误和重试状态。公共留言卡片下方显示开发者回复。

验证账号越权、游客与失效令牌、撤销权限、严格契约与旧版响应、分页、审核/禁言、回复幂等、可见范围和级联清理；客户端验证入口显隐、审核操作、回复草稿和显示。执行 `npm run check`、Cloudflare 类型检查与测试及 Web 导出。文档同步说明权限配置和部署顺序：先 D1 迁移，再 Worker secret/API，最后客户端。

参考：[Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/)。
