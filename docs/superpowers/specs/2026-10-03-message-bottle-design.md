# 留言瓶设计

## 目标

在黑洞英语 Expo 客户端（iOS／Android／Web）的主导航新增「留言瓶」，用户可以提交产品意见，并在同一页面查看所有用户发布的留言。留言存入云端，跨设备共享；阅读和口语模式均可进入。

## 方案选择

用户于 2026-10-03 确认采用实名提交并标注用户名。本文件按该选择修订，并继续实施。

留言提交需要已登录的邮箱或微信账号，公开列表显示用户名、留言内容和时间，自己的留言额外标注「我」。现有账号尚无用户名，首次留言时设置 2–24 字的用户名并保存到账号，后续使用同一署名。用户名按规范化和忽略大小写保证唯一，不公开邮箱、微信信息或用户 ID。用户名在本功能内设置一次，避免随意冒用其他账号的署名。

之前考虑的匿名提交和审核后公开不进入本次实现；留言发布后立即公开。游客也可浏览所有留言，登录后才能投递。

## 导航与页面

- 阅读模式：外刊／书架／词库／留言瓶／我的。
- 口语模式：素材／文件／留言瓶／我的。
- 宽屏沿用侧边栏，窄屏沿用底部标签栏；沿用现有主题、字号、朱橙按钮与轨道标记。
- 页面上方显示标题「留言瓶」和说明「把想法装进瓶子，让黑洞英语变得更好。」
- 已登录用户的输入区提供用户名、多行文本框、字数和「投递留言」按钮，提交前明确提示「留言与用户名会公开给所有人」。首次设置用户名时可编辑，已有用户名时显示固定署名；游客显示「登录后留言」入口。
- 内容去除首尾空白后为 1–1,000 字；保留段落和换行。空白内容不可提交。
- 提交中锁定按钮；成功后清空输入并刷新最新列表；失败保留草稿并显示中文原因。
- 列表标题为「所有留言」，按发布时间倒序展示，显示用户名、发布时间和完整内容。
- 每页默认 20 条，通过「加载更多」访问历史留言；支持刷新。首次加载、空列表、读取失败、加载更多失败分别提供明确状态和重试入口。
- 手机键盘弹出时输入和提交按钮可操作；内容按纯文本呈现；浅色、深色和宽屏均适配。

## 契约与接口

所有输入和输出 schema 在 `packages/contracts/src/index.ts` 定义，并使用严格 Zod 校验。

- `POST /v1/message-bottles`：请求 `{ username: string, content: string }`，使用现有 Bearer 安装身份和 `Idempotency-Key`，校验已登录的注册账号后返回创建的留言。首次设置用户名和发布留言原子提交；其他账号不能使用同一用户名，已有用户名不能传入另一署名。
- `GET /v1/message-bottles`：使用安装身份，返回所有用户的公开留言；支持 `limit`（默认 20，最大 50）和分页游标。
- `GET /v1/message-bottles/profile`：返回当前账号的 `username`（未设置时为 `null`）和 `canPost`，以服务端身份判断是否允许发布。
- 留言 DTO 仅包含 `id`、`username`、`content`、`createdAt` 和 `isMine`。
- 分页响应包含 `items` 和 `nextCursor`；无后续数据时 `nextCursor` 为 `null`。
- 游标按 `createdAt` 与 `id` 共同排序，确保相同时间的留言不会遗漏或重复；无效游标和超出范围的参数返回稳定校验错误。
- 同一幂等键重放相同内容返回原留言；同一键用于不同内容返回冲突。客户端网络失败后保留原键供同一草稿重试。
- 首次使用时复用现有匿名安装身份初始化，列表和提交均可直接使用。
- 提交复用请求限流，同一账号每 10 分钟最多发布 5 条新留言；幂等重放不产生第二条留言，也不占用新的发布次数。
- 留言不消耗阅读练习额度，也不触发 AI 任务。

## 存储与后端

新增 `message_bottles` 表，保存 UUID、内部作者关联、发布时用户名、内容、创建时间，并为倒序分页建立索引。`users` 表增量增加可空的用户名和唯一规范化用户名列；已有账号初始保持未设置。表和迁移只增不改，不修改历史业务数据。

正式 Web 的 Cloudflare Worker 使用 D1，因此增加 D1 迁移和对应路由。Fastify 本地服务使用 Neon，因此同步增加 Drizzle 表定义、由 `db:generate` 生成的迁移和模块路由。两套实现复用共享契约，并保持排序、校验和幂等行为一致。

列表查询跨用户读取公开内容；提交仅使用经身份校验得到的作者，不接受客户端传入作者。日志和错误不输出留言正文或身份凭证。SQL 使用参数绑定。

## 验证

契约测试覆盖空白、内容长度、未知字段、分页参数和响应边界。服务端测试覆盖身份校验、跨用户可见、私密身份不出现在响应、相同键重放、不同内容冲突、稳定分页和提交频率约束。数据库集成测试遵循现有随机 `app_test_*` 隔离 Schema 规则。

客户端测试覆盖两种模式的导航、游客浏览和登录入口、首次设置用户名、实名显示、提交成功、草稿保留、防重复提交、公共列表、空状态和翻页错误重试。后端测试额外覆盖游客不可提交、用户名唯一性和固定署名校验。完成后运行全工作区 `npm run check`、Cloudflare API 类型检查和相关测试、服务端构建与 Web 导出。

上线顺序为先执行相应数据库的增量迁移，再更新 API 和客户端。生产部署另行执行；当前工作范围为实现、验证并给出可审查的代码。
