# 用户名

## 功能

每个注册账号都有一个公开的用户名，用于留言瓶署名：

- **注册时设置**：登录／注册页新增选填的「用户名」输入框。新建账号时使用，留空则由服务端自动生成；已有账号登录时忽略该字段。
- **老账号回填**：迁移 `0009_usernames.sql` 为所有已注册、未删除、尚无用户名的账号回填用户名（规则见下）。
- **随时修改**：「我的」页的用户名旁有「修改」，留言瓶发布框的「公开署名」旁也有入口，进入同一个修改页（`/username`）。
- **旧版客户端**：不传 `username` 也能注册，服务端自动生成。已发布的留言保留发布时的署名，改名不会回改历史留言。

## 规则

| 项目 | 规则 |
| --- | --- |
| 长度 | 2–24 个字符（NFKC 规范化、去首尾空白之后计算） |
| 字符 | 各语言文字、数字、`_`、`·`、`.`、`-`；不含空格、`@`、表情等 |
| 必须包含 | 至少一个文字或数字（不能是 `..`、`___` 这样的纯标点） |
| 唯一性 | 忽略大小写和全角差异：`Alice`、`alice`、`ＡＬＩＣＥ` 是同一个名字。数据库唯一索引 `users_username_key_unique`（`username_key`）保证 |
| 保留字 | `admin`、`root`、`support`、`官方`、`客服`、`黑洞英语` 等，忽略大小写并忽略 `_ . - ·`（`a.d.m.i.n` 同样被拦截）。名单见 `packages/contracts` 的 `RESERVED_USERNAMES`，只是尽力而为的冒充防护 |

规则只有一份实现：`packages/contracts/src/index.ts` 的 `checkUsername`。App 的表单校验和两套后端的校验都调用它，所以提示一致。读取已保存的名字时使用更宽松的 `UsernameSchema`（只检查长度和字符集），留言瓶上线时用户自行设置的名字不会因为新增的保留字规则而无法读取。

## 接口（仅 Cloudflare Worker）

| 接口 | 说明 |
| --- | --- |
| `POST /v1/auth/email` | 请求新增可选 `username`。**响应结构不变**（现有客户端用 strict schema 解析响应，多一个字段就会解析失败） |
| `GET /v1/account` | `{ kind: 'guest' \| 'registered', username: string \| null }`。已注册但没有用户名的账号在此补发（见「补发」） |
| `PUT /v1/account/username` | `{ username }`，返回新的账号资料。游客 403，名字被占用 409（`STATE_CONFLICT`），格式不合法 400（提示为具体原因） |

用户名被占用时，`POST /v1/auth/email` 返回 409，整个批处理回滚，**不会创建账号**，并且在做密码哈希之前就会拦截。

旧 Fastify 服务（`server/`）没有这些账号接口，也不会保存注册时提交的 `username`；它只用于本地开发，见「已知限制」。

## 存储与迁移

`users.username`、`users.username_key` 和唯一索引由 `0008_message_bottles.sql` 创建。**本次没有改动表结构**，新增的 `0009_usernames.sql` 只回填数据。

回填规则：

1. 取账号最早绑定的邮箱 `@` 前的部分，转小写，`+` 和 `'` 换成 `_`，最多 24 个字符。
2. 同一前缀里最早注册的账号保留原名；其余账号改为「前缀（最多 15 个字符）＋ `_` ＋ 账号 ID 前 8 位」。
3. 下列情况不使用邮箱前缀，改为 `用户_` ＋ 账号 ID 前 8 位：没有邮箱（例如只用微信登录，openid、unionid 永远不会用作用户名）、少于 2 个字符、含 `[a-z0-9_.-]` 以外的字符、没有字母数字、命中保留字，或**含连续 6 位及以上数字**（可能是手机号或 QQ 号）。
4. 已有用户名、游客、已删除账号保持不变；重复执行没有副作用。
5. 写入前有断言（`transaction_guards`）：回填结果之间或与已有用户名重名时迁移中止，不写入任何用户名。

> 用户名会在留言瓶里公开展示，所以回填**没有**直接使用完整邮箱：完整邮箱会泄露隐私，也不符合用户名字符规则（`@` 不在字符集内）。第 3 条同理。如果产品上想改成统一使用匿名名，只需改 `0009_usernames.sql` 里的 `base` 计算和 `cloudflare/api/src/auth/username.ts` 的 `deriveUsernameBase`；`username-migration.test.ts` 会校验两处一致。

### 补发

迁移执行之后、新版 API 上线之前，旧版 API 仍可能创建没有用户名的新注册账号。新版 API 在 `GET /v1/account` 时为这类账号补发（候选顺序：邮箱前缀、带随机后缀的前缀、`用户_` ＋ 随机串；撞上唯一索引就换下一个）。留言瓶原有的「首次投递时设置用户名」路径仍然保留，用于兼容这类账号。

## 兼容性

- **旧版 App／小程序**：请求体不含 `username`，仍可注册（小程序只发 `{ email, password }`），所有响应结构不变。
- **新版客户端 → 旧版 API**：旧 API 对 `username` 字段会返回 400（请求 schema 是 strict）。**必须先发布 API，再发布 Web 和原生客户端。** 留空用户名时客户端不发该字段，不受影响。
- **回滚**：迁移只写数据。回滚 API 不需要动数据库；若要撤销回填，用 D1 Time Travel 恢复到执行迁移前的书签。

## 上线顺序与命令

下面的命令**本次均未执行**（按要求只做本地开发和验证）：

```powershell
# 0. 回滚点与备份（只读）
npx wrangler d1 time-travel info waikan-core --config cloudflare/api/wrangler.jsonc
npx wrangler d1 export waikan-core --remote --output backup-before-0009.sql --config cloudflare/api/wrangler.jsonc

# 1. 执行增量迁移。0008 尚未执行时会先执行 0008，再执行 0009
npm run cloudflare:d1:migrate:api

# 2. 发布 API，再发布 Web 和原生客户端
npm run cloudflare:deploy:api
```

`npm run cloudflare:d1:migrate:api` 等价于 `wrangler d1 migrations apply waikan-core --remote`，凭据 `CLOUDFLARE_D1_API_TOKEN` 和 `CLOUDFLARE_ACCOUNT_ID` 来自 `cloudflare/.env.local`。

迁移后核对（只读）：

```sql
-- 应为 0
SELECT count(*) FROM users WHERE kind = 'registered' AND deleted_at IS NULL AND username IS NULL;
-- 两个数应相等
SELECT count(*) AS named, count(DISTINCT username_key) AS distinct_keys FROM users WHERE username IS NOT NULL;
-- 应为 0（临时表已删除）
SELECT count(*) FROM sqlite_master WHERE name = 'username_backfill';
```

## 本地演练

除了 `node:sqlite` 单元测试，迁移还通过 wrangler 自带的本地 D1（`--local`，workerd 引擎）按真实的迁移流程演练过：先应用 `0001`–`0008` 并写入夹具数据，再应用 `0009`。演练只访问本地状态，没有访问线上。

## 验证

- 契约：6 个文件、74 项测试（新增 13 项）；各工作区类型检查通过。
- Worker：21 个文件、229 项测试（新增 72 项）。`username-migration.test.ts` 在 25 个夹具账号上执行迁移，并把 SQL 回填与 TypeScript 的 `deriveUsernameBase` 逐个对拍；变异测试确认删掉手机号规则、颠倒先后顺序或删掉重名断言都会让测试失败。
- 客户端：112 个文件、631 项测试（新增 32 项）；Lint 0 错误，警告数与改动前相同（24 条）。
- 旧服务：不连接 Neon 的情况下 404 项通过；其余 90 项是需要 `TEST_DATABASE_URL` 的数据库集成测试，没有运行。

## 已知限制

- **旧 Fastify／Neon 服务没有同步**：没有账号接口，也不保存注册时的 `username`。它只用于本地开发（线上由 Cloudflare Worker 提供服务，Render 仅转发），并且它的数据库测试需要 Neon 连接，本次没有使用。若要在本地开发里完整验证，需要补一份 Drizzle 迁移和对应服务代码。
- 留言瓶「首次投递时设置用户名」的旧路径只检查长度和字符集，不检查保留字；这个路径只对尚无用户名的账号生效，正常情况下几乎不会出现。
- 保留字名单是尽力而为的拦截，不防形近字（例如西里尔字母）冒充。
- 回填使用邮箱前缀意味着一部分老用户的默认公开名字来源于邮箱，建议在发布说明里提醒用户可以到「我的」修改。
