## 实际检查

- 视频中的两篇文章为「本周全球政治要闻」和「南非如何避免沦为黑帮国家」。生产入口上的两份录音范围请求返回 206，类型为 `audio/mpeg`，64 KiB 范围响应在本次电脑网络下约 1.4 秒完成。
- 两份原始 MP3 均可正常解码，编码与可播放的内置 AI 军备竞赛录音一致，均为 44.1 kHz 单声道 MP3。电脑 HTTP 检查和解码不能证明真机 AVPlayer 可以正常读取远程资源。
- 使用一个随机的、未登记的安装令牌请求生产 `/v1/sentence-translations`，得到 401 / `UNAUTHORIZED`。该请求未创建账号、未写入词库，也未调用 AI。客户端获取安装令牌只负责本地生成与读取，外刊浏览不会自动登记身份；此前概述页面吞掉了这个区别。
- 用本地当前 EvoLink 配置翻译南非文章的英文概述，约 2.4 秒成功返回中文。此检查没有经过生产 Worker，不能证明生产翻译凭据或手机请求正常。
- 概述之前被限制为 30 秒，但服务端翻译生成期限为 120 秒；合法的较慢请求会被客户端提前中止。缓存读取和写入原先也可能在网络计时之外无限等待。

上述事实证明了未登记身份、过短期限、缓存阻塞等代码缺陷，尚未证明它们就是用户设备的实际失败原因。用户随后补充：邮箱登录本身也显示「连接超时，请重试」。因此不能把这次反馈仅归因于缺少登录身份，当前优先检查手机到公开入口的连接与登录请求链路。

已开启入口 Worker 和 API Worker 的临时实时监听，电脑发出的未认证翻译验证请求同时出现在两端，均返回 401。用户反馈已再次尝试登录，监听窗口暂未见登录请求；由于点击时间与监听窗口不能精确关联，不能据此断言请求完全没有发出。用户随后通过二维码确认，同一部 iPhone 的 Safari 可以播放南非文章的同一份远程录音。这确认了浏览器到录音服务的可达性，不能证明 App 的 URLSession 请求、身份登记或翻译路径正常。

安装包的 `Info.plist` 未设置 `ReactNetworkForceWifiOnly`，HTTPS 请求也没有受到禁用任意 HTTP 的 ATS 配置影响；Hermes 字节码的 `getApiBaseUrl` 使用生产公开入口，不存在开发局域网地址覆盖。build 32 使用 React Native 全局 fetch，上一版默认 Expo fetch 的失败反馈尚不能仅靠切换全局实现解释。

## 本轮客户端改动

1. 音频首次采用流式加载；点击失败重试时重建播放器，并用 SDK 57 的 `downloadFirst` 将录音下载到设备后加载。重建同时重置旧的错误事件，后续下载重试也会重新创建播放器。首次等待上限仍为 15 秒，下载等待上限为 60 秒，保留所选倍速。
2. 概述显示固定的安全错误文案，区分身份未登记或失效、凭据读取失败、连接失败、AI 服务不可用与限流。身份错误提供登录入口，返回页面后重新读取概述；不自动创建身份或替用户确认年龄。
3. 概述期限与句子翻译统一为 150 秒，覆盖服务端生成期限；英文原文在等待期间仍立即可读。
4. 缓存读取最多等 1 秒，缓存写入不阻塞已取得的中文概述；共享请求覆盖缓存读取阶段。
5. 登录失败提示和设置页增加「连接检测」。检测现有安全凭据读取、公共 API 契约、登录 POST 路径及两字节录音范围读取；生产 RN fetch 配置下比较当前实现与独立导入的 Expo fetch。登录路径使用契约拒绝的空请求，验证发生在身份登记之前，不会创建账号。检测不生成或清除本地凭据，只报告固定类别、步骤、状态、耗时和安全请求编号。
6. 正常 API 调用发生错误时，在内存中保留最近五次失败的步骤，区分凭据读取、连接、响应正文和契约校验。记录不包含请求 URL、路径参数、正文、邮箱、密码、令牌或原生错误文本；检测结果可复制以便真机排查。

这些改动不在 build 32 中。生产 iOS 构建 `85dd0ba0-ce40-442c-8dbe-00cde4671c55` 已完成，已下载 IPA 核对原生版本号为 33、bundle ID 不变，包内包含新的连接检测路由及错误类别。TestFlight 提交编号为 `df5363e4-3150-4754-9241-61c02686771b`；第一次附带测试说明的提交被 EAS 套餐限制拒绝，移除附加说明后成功提交，未改变安装包。Apple 查询确认 build 33 于北京时间 2026-09-26 16:25:38 上传，处理状态 `VALID`，内部测试状态 `IN_BETA_TESTING`，已可供现有内部测试者更新。不能以构建成功或测试版本可用替代真机验收。
