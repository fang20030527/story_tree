# 2026-10-05 账号合规、每日额度、留言审核与加载速度

本轮根据 [全面审查](2026-10-05-review-fixes.md) 后确定的待办完成：免费额度每天重置并按设备共享、AI 总量上限、注销账号与隐私政策、留言瓶举报屏蔽与人工审核、生词删除与修改，以及影子跟读加载速度。

## 影子跟读为什么慢

先说结论：**不是词库和首页的全量计算导致的**。打开影子跟读不会请求词库或首页接口；慢在它自己的请求链：

1. 读取本机缓存后，等「共享素材目录 + 账号文件第一页」返回；
2. 再请求「这部片的完整字幕 + 练习状态」；
3. 字幕到了才显示播放器，播放器再请求一次「播放签名」；
4. 最后视频才开始从 R2 加载（MP4 已是 faststart，但要先下载约 1 MB 的索引）。

每个请求在服务端还要先写一次 D1（IP 限流），再进 Durable Object，每次都从 R2 重新读取并校验目录和最多 2 MB 的字幕。2026-10-05 从开发电脑实测（经代理落在波士顿节点，复用连接）：静态页面约 0.4 秒，目录 0.85 秒，单部影片字幕 1.0 秒，长播客字幕（709 KB）1.7–2.3 秒，播放签名 0.85 秒。三轮串行请求加起来，在打开影片前就要 3 秒左右，网络更差时更久。

已修复：

- **本机已有字幕时立即显示**，后台再刷新；刷新失败也不打断练习。没有缓存时，字幕和目录**同时**请求，不再先等目录。
- **提前签名播放链接**：素材详情页和影子跟读页一知道是平台影片就开始签名，播放器挂载时直接使用。
- **Durable Object 内存缓存**：目录缓存 1 分钟（新发布最多 1 分钟后可见），字幕按「素材 + 版本」缓存最近 6 部，再次打开不再读 R2、不再重新校验；登录用户读取平台字幕时不再重复校验整份字幕。
- **IP 限流改用 Workers 限流绑定**（`IP_RATE_LIMITER`，每 IP 每分钟 600 次），每个 API 请求不再先写一次 D1。未绑定时自动退回 D1 计数。

顺带处理了词库的全量计算（它会拖慢同一个 D1 数据库上的其他请求，也会在词量变大后超出免费套餐每次 10 ms 的 CPU）：

- 词库列表和首页统计**不再每次重数全部答题记录**。每次作答都在同一个 D1 事务里按答题数更新复习状态，读取时重数是多余的。
- 词库列表用手写的结构检查代替逐词的 zod 校验，翻页一致性摘要直接使用库里保存的状态文本，排序不再用 `localeCompare`。
- 阅读页和自测题的生词高亮原来每 50 个词请求一次 `/v1/vocabulary-words`（每次都在服务端重排全部单词），现在改为一次 `GET /v1/vocabulary-terms`。

## 免费额度：每天重置，账号、设备、网络共用

- 北京时间每天 0 点恢复，默认每天 3 次（`FREE_PRACTICE_LIMIT`）。
- 一次练习同时占用**账号**、**设备**和**网络**当天的次数，三者都有剩余才能创建：
  - 设备：客户端生成随机设备编号，经 `X-Device-Id` 请求头发送。iOS 存在钥匙串（`AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`，退出登录、删除重装都不变）；网页存在 localStorage（同一浏览器的所有标签页共用，登录凭据仍只在当前标签页）；小程序存在微信本地存储。退出登录、新注册账号、开新标签页都不会增加次数。
  - 网络：IPv4 地址或 IPv6 的 /64 前缀，默认每天 10 次（`FREE_PRACTICE_IP_DAILY_LIMIT`）。这是给无痕窗口、换浏览器留的兜底；运营商 NAT 会让很多人共用一个地址，所以比设备上限宽。经香港中转、无法核实真实地址的请求不计网络额度。
  - 服务端只保存设备编号和网络地址的 SHA-256 摘要，记录不关联账号，**注销账号不会恢复当天的次数**；两天后由定时任务删除。
- 生成失败释放额度时，设备和网络的次数一起恢复。无限练习账号不占用设备次数。
- 旧版 App 不发送设备编号，只按账号和网络计数。
- 已知局限：网页端换浏览器或开无痕窗口会得到新的设备编号，只受网络上限约束；有意伪造请求头的脚本绕得过设备限制，由下面的 AI 总量上限兜底。

## AI 总量上限

- 全站每天（北京时间）调用 EvoLink 的总次数上限 `AI_DAILY_CALL_LIMIT`，默认 2000，包括练习生成、翻译、图片识别和口语点评。每次真实调用前原子计数（`ai_usage_daily` 表）。
- 达到上限后不再接受新的练习、翻译、图片导入和口语点评，返回「今天的 AI 服务用量已达上限，请明天再试」；已经开始的任务还能使用 25% 余量完成，超出余量的调用直接拒绝。
- 每个账号 24 小时内最多 500 次即时查词和句子翻译，避免单个账号用完全站额度。
- 按预算调整 `wrangler.jsonc` 里的 `AI_DAILY_CALL_LIMIT` 后重新发布 API 即可。

## 注销账号与隐私政策

- 「设置 → 账号与隐私」新增：已屏蔽的用户、隐私政策、注销账号；「关于」里显示联系邮箱。登录页提示同意隐私政策和数据存放在境外。
- `POST /v1/account/delete`：邮箱账号需要密码（`ACCOUNT_PASSWORD_REQUIRED` / `EMAIL_AUTH_FAILED`，10 分钟最多 10 次），游客和微信账号直接确认。一次 D1 事务里：私有录音和口语文件进入清理队列（每分钟的定时任务从 R2 删除），删除这个账号资源的排队任务，删除 `users` 行，其余数据全部级联删除。导入用的临时文件随后尽量立即删除（桶本身 8 天过期）。
- 客户端注销后清除本机登录、这个账号的口语缓存和进行中的练习/导入编号；响应丢失后重试遇到「凭据无效」视为已注销。
- 隐私政策正文在 `app/src/features/legal/privacyPolicy.ts`，网页地址 `https://blackholeenglish.com/privacy`（静态导出，可以填进 App Store Connect）。

**上线前需要你确认或补充：**

1. 联系邮箱 `support@blackholeenglish.com` 需要真实可收信。域名在 Cloudflare，可以用免费的 Email Routing 转发到自己的邮箱。
2. 隐私政策里的运营者目前写的是「黑洞英语」，个体户执照办下来后补上经营者名称。
3. 面向中国大陆用户时，《个人信息保护法》要求跨境传输取得单独同意，工信部也要求首次启动时弹出隐私政策并取得同意。现在只有登录页的提示，建议后续加首次启动的同意弹窗。

## 留言瓶：举报、屏蔽和人工审核

- 每条别人的留言右侧有「···」：**举报**（垃圾广告、辱骂骚扰、色情低俗、违法违规、其他）后，这条留言对举报人立即隐藏；**3 个不同的人举报**后对所有人隐藏，等待审核。**屏蔽**作者后看不到对方的任何留言，可在「设置 → 已屏蔽的用户」解除。
- **先审后发**：`MESSAGE_BOTTLE_REVIEW=pre`（默认）时新留言进入「待审核」，只有作者能看到并标明「审核中 · 仅自己可见」，审核通过后公开。改成 `post` 则立即公开，只有被举报的留言进入审核。
- **审核后台**：`https://blackholeenglish.com/v1/admin/moderation`。用 `wrangler secret put ADMIN_TOKEN --config cloudflare/api/wrangler.jsonc` 设置至少 24 位的口令后启用；未设置时后台和接口都返回 404。可以按「待审核 / 被举报 / 已隐藏 / 最近留言」查看，通过、隐藏、删除留言，禁言作者（同时隐藏其全部留言）或解除禁言。口令错误按 IP 限流（10 分钟 20 次）。
- **提醒邮件**（可选）：设置 `MODERATION_NOTIFY_EMAIL` 后，有留言待审或新举报时最多每 30 分钟发一封提醒，复用密码重置的 Resend 发信配置。
- 留言继续显示发布时的署名（与原有的改名测试一致）。改名后旧名字可以被别人注册，这个冒用风险仍然存在；有了审核和举报后可以人工处理，需要彻底解决时可以给释放的旧名字加一段保留期。
- 社区规则写在投递框下方：禁止广告、辱骂、色情和违法内容，违规留言会被删除、作者会被禁言（App Store 审核指南 1.2）。

## 生词删除与修改

- 生词本每个单词下方有「修改」「删除」。删除是软删除：生词本、高亮和自动选词不再出现，以前的练习文章和作答记录保留；之后重新保存同一个词会回到「在学」。
- 编辑页可以：
  - 修改释义和例句（原地修改；与同一单词的其他释义重复时提示）；
  - 删除某一个释义（只剩一个释义时请删除整个单词）；
  - 修改拼写：全部释义移到新拼写的单词，新单词重新安排复习；改成已有的单词时合并相同释义；只改大小写则原地修改、不影响复习。
- 接口：`DELETE /v1/vocabulary-words/:id`、`PATCH /v1/vocabulary-words/:id`（需要 `Idempotency-Key`）、`PATCH|DELETE /v1/vocabulary-items/:id`。小程序暂未提供删除和修改入口。

## 发布步骤

1. `npm run cloudflare:d1:migrate:api`：应用 `0011_daily_quota.sql`（额度事件、AI 用量表和账本索引）和 `0012_message_moderation.sql`（留言状态、举报、屏蔽、禁言）。两份迁移只增加表、列和索引，旧版 API 在迁移后仍可运行。
2. `npx wrangler secret put ADMIN_TOKEN --config cloudflare/api/wrangler.jsonc`；可选设置 `MODERATION_NOTIFY_EMAIL`。
3. `npm run cloudflare:deploy:api`。新的 `ratelimits` 绑定在部署时创建；如果账户不支持，删除 `wrangler.jsonc` 里的 `ratelimits` 一节即可，代码会退回 D1 计数。
4. 重新导出并发布 Web（`npm run cloudflare:prepare:web` → `npm run cloudflare:deploy:web`）。
5. iOS 需要新构建（设备编号、注销账号、隐私政策、举报屏蔽、生词编辑、影子跟读加载）。旧版 App 与新 API 兼容：留言列表只对新版返回审核状态，旧版只按账号和网络计算额度。
6. 小程序重新构建上传。

**必须先发布 API 再发布客户端**：新客户端依赖 `/v1/vocabulary-terms`、`/v1/account/delete`、留言的 `includeStatus` 等新接口。

## 苹果内购怎么接（还没有实现）

**iOS 上的 VIP 只能走苹果内购**，与有没有营业执照无关：审核指南 3.1.1 要求在 App 内解锁功能或内容必须使用 IAP，中国区没有外部支付的例外。执照办下来后，微信支付、支付宝可以用在网页版和安卓，但不能用于 iOS App 内的 VIP。

1. **账号准备**：个人开发者账号就能卖 IAP，不需要执照。在 App Store Connect「协议、税务和银行业务」签署付费 App 协议，填个人银行账户和税务信息（W-8BEN）；申请小型企业计划，佣金 15%。
2. **商品**：建一个订阅组「VIP」，放月度和年度自动续期订阅（可加首月优惠），或做一个非消耗型的终身 VIP。订阅页要写清价格、周期、自动续费和取消方式，并放用户协议（EULA）和隐私政策链接（审核指南 3.1.2）。还要有「恢复购买」按钮。
3. **客户端**：用 `expo-iap`（StoreKit 2）或 RevenueCat 的 `react-native-purchases`，需要新的 EAS 构建，不能 OTA。购买时把账号的 UUID 作为 `appAccountToken`，成功后把交易 ID 发给服务端，服务端确认后再调用 `finishTransaction`。
4. **服务端（Worker）**：
   - 用 App Store Server API 按交易 ID 查询交易（用 In-App Purchase 密钥签 ES256 JWT，Worker 的 WebCrypto 可以签）；
   - D1 记录 `original_transaction_id`、账号、商品和到期时间；
   - 接 App Store Server Notifications V2 处理续费、退款和过期，验证通知的 JWS 证书链；
   - VIP 有效期内视同无限练习，把额度判断里的 `user_practice_access` 换成「有效订阅或无限开关」。
5. **测试**：TestFlight 默认走沙盒环境，在 App Store Connect 建沙盒测试账号即可完整测试购买、续费和退款。
6. **相关提醒**：在中国大陆上架需要 App 备案号。以个人主体备案时，多数地区不允许留言、评论这类交互功能，留言瓶可能要等个体户主体备案后再开放，建议先向备案服务商确认。

如果改用 RevenueCat，服务端只需接它的 Webhook，开发量更小，但隐私政策要加上这个第三方。

## Fastify 后端能不能删

能删大部分，但不能整个删：

- **线上转发服务**：Render 上的 `compat-proxy-entry` 只为直连 `waikan-api.onrender.com` 的旧安装包转发到 Cloudflare。TestFlight 构建上传 90 天后自动失效，build 31 起已经直连 Cloudflare。等最后一个指向 Render 的构建失效（或在 Render 控制台确认几天没有请求）后，就可以停掉 Render 服务并删除 `render.yaml`。
- **代码**：Worker 直接引用 `server/src` 里 26 个模块（出题提示词和校验、FSRS 排期、生词规范化、错误码、EvoLink 客户端、字幕与发音、导入解析等），连同它们的依赖共 28 个文件，要先搬到独立的共享包（例如 `packages/core`），并改掉 Worker 的相对路径。其余 86 个非测试文件（约四分之三）是 Fastify 路由、PostgreSQL/Drizzle 仓储和迁移、Neon 任务队列、插件和入口，都可以删除，还能去掉 `pg`、`drizzle-orm`、`fastify` 等依赖。
- **内容资源**：`server/content`（口语素材目录）和 `server/assets`（外刊正文和插图）被发布脚本使用，要保留或搬到独立的内容目录。

建议单独做一轮：先建共享包并迁移引用、跑全部测试，再删除 Fastify 专用代码，最后停 Render。
