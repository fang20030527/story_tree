## 已完成的代码修复

API 客户端增加 30 秒整体等待上限，超时终止网络请求并返回可重试的中文提示，复用页面现有重试按钮。覆盖凭据读取、响应头及响应正文阶段；若凭据在超时后才返回，不再发出请求。没有增加自动重试，写请求继续依赖原有幂等键。

## 下一步如何确定真正的提速措施

1. 若闲置后的首次打开慢、紧接着重开快，核对实际 Render 套餐及请求时间附近的启动日志；确认休眠后，将 API 改为常驻实例可消除这部分等待。
2. 若每次都慢，结合实际 `/v1/vocabulary-words` 的请求 ID 检查总耗时、账号锁等待、历史答案聚合及复习状态回填耗时，再决定优化哪一步。无需向日志输出令牌、正文、单词或数据库地址。
3. 查询优化方向是将历史回填移出常规读取、在写入时维护复习状态、用数据库分页；必须保留历史答案兼容、全词库分类计数、分页一致性及复习规则，不能直接删除同步步骤。
4. 本地词库缓存可改善再次打开体验，但应按账号隔离，在切换账号和修改词库后失效，并明确刷新状态。
