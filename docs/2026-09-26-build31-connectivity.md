排查日期：2026-09-26。目标是生产客户端在蜂窝网络和 Wi-Fi 下访问同一公开服务，并在短暂断连后恢复读取。

## 已核实的事实

- 用户安装的是 iOS build 31，EAS 构建 ID 为 `13fa2558-a611-4bbb-8fdd-c6379e04d819`。构建日志中的 API 地址是 `https://waikan-web.zhenyufang162.workers.dev`，不是本地开发地址，也不是旧 Render 地址。
- 用户在手机浏览器通过 5G 访问业务接口，收到 `UNAUTHORIZED` JSON。直接打开接口没有携带 App 的安装令牌，返回 401 是预期行为；它证明这次浏览器请求到达了服务，不能证明 App 的凭据读取、联网权限或网络实现正常。
- 用户返回 App 重试后仍显示连接超时。对应时间段的 Cloudflare 入口统计未看到这次 App 请求。统计有采样和延迟，因此不据此断言请求一定没有发送。
- 用户已确认 iPhone 为黑洞英语同时允许 Wi-Fi 与蜂窝数据，排除了「仅允许 Wi-Fi」这一设置原因。
- 实际 API 的 `/health/ready` 返回正常；公开入口的 `/v1/dashboard`、`/v1/vocabulary-words` 能返回预期的未认证错误。Web 入口的 `/health/ready` 当前会回退到静态页面，不能将它的 HTTP 200 当作 API 健康证据。
- 使用生产 D1 的只读适配器执行现有 dashboard 和词库处理函数，6 个有词库数据的用户共 12 次读取均为 200，耗时 245–865 毫秒。此检查没有走真机网络及安装令牌认证，不能替代真机验证；没有创建账号、调用 AI 或修改词库。

目前没有证据将本次超时归因于 Render 冷启动，也没有证明 Expo fetch 或安全存储就是这台手机的实际故障源。

## 代码修复

1. 安全凭据读取增加 5 秒等待上限。原来共享的读取 Promise 如果一直挂起，后续重试会始终等待同一个 Promise；现在读取超时会结束共享任务，允许下一次重新读取。迟到的空结果不会继续创建新身份。未完成的存储写入仍共享，以防重试覆盖安装身份；调用方等待仍有上限。
2. GET/HEAD 在连接失败、单次请求超时或凭据读取超时后，使用新的请求信号自动重试一次。单次读取等待上限为 12 秒，仍受原有总体等待上限约束。写请求以及认证、限流等明确服务错误不会自动重放。
3. 词库首页在前台恢复且页面仍聚焦时重新加载；生词本已有同类逻辑。用户从网络设置返回 App 后可恢复刷新。
4. 生产构建设置 SDK 57 官方提供的 `EXPO_PUBLIC_USE_RN_FETCH=1`，使用 React Native 全局 fetch。此项是兼容性调整，尚需新版真机验证，不能视为已证明的根因修复。
5. 生产构建要求 API 配置为公开 HTTPS 域名，阻止将 localhost、局域网 IP 或带业务路径的地址打入发布包。开发环境保留局域网调试方式。
6. 请求超时提示改为「连接超时，请重试」，凭据读取超时单独提示「读取登录信息超时，请重试」，不再默认暗示服务器正在启动。底层凭据错误不会向用户暴露原始内容。

## 新版真机验收

这些客户端改动不会改变已安装的 build 31，需要更新到 build 32 才能验证。真机验收结果尚待用户反馈；验收须保留原账号与词库，并分别检查：

| 场景 | 预期 |
| --- | --- |
| 关闭 Wi-Fi，使用蜂窝网络首次打开词库和生词本 | 统计及列表加载成功 |
| 关闭蜂窝数据，使用 Wi-Fi 打开同一账号 | 同一份词库正常加载 |
| 读取过程中从 Wi-Fi 切换到蜂窝网络，或反向切换 | 请求成功，或短暂失败后自动重连／点击重试恢复 |
| App 进入后台，调整网络后返回前台 | 当前词库页面重新加载 |
| 短暂断网后恢复 | 不无限等待，不切换安装身份，重试能恢复 |
| 创建练习、提交答案、登录 | 不因网络重连自动重复发送写请求 |

若仍失败，先记录新版显示的是连接错误还是凭据错误，并结合入口请求记录定位下一步。iOS 对 App 的无线数据权限需要允许 Wi-Fi 与蜂窝网络；客户端不能绕过系统设置。公网域名在不同运营商下的实际可达性也必须以真机测试确认。
