# Cloudflare AI 生成中断修复

## 原因与修复

2026-09-27 用户提交的四主题练习全部停在 10%，三个自动重试后均显示 `AI_UNAVAILABLE`。D1 记录确认失败发生在生成正文之前。

同一 EvoLink 配置在本机请求成功。使用 Miniflare/workerd 运行生产 AI 客户端后，复现了 `Illegal invocation: function called with incorrect this reference`，外部服务收到的请求数量为 0。共享客户端把未绑定的原生 `fetch` 存在实例属性中，通过 `this.fetchImpl(...)` 调用时，接收者变成了客户端对象；Cloudflare 原生函数拒绝该调用，客户端随后把异常转换成了通用 AI 不可用提示。相关运行时规则见 [Cloudflare 官方错误说明](https://developers.cloudflare.com/workers/observability/errors/#illegal-invocation-errors)。

`server/src/infrastructure/ai/evolink-client.ts` 的默认网络函数改为 `globalThis.fetch.bind(globalThis)`。显式注入的测试函数继续使用原行为，请求格式、模型、超时、输出校验和限流错误处理保持原约定。Cloudflare API 引用同一客户端，因此服务端发布即可生效，无需重新安装手机 App。

## 回归验证

新增 `cloudflare/api/src/ai/provider.runtime.test.ts`，在与生产相同兼容日期和标记的 workerd 中调用真实 provider，仅替换外部服务的响应。测试覆盖生成和审核两次原生网络请求，以及上游 429 的可重试错误与密钥隔离。修复前两个测试失败，绑定修复后测试通过。

线上复核还发现修订流程会覆盖此前审核反馈：模型修好单词间距和复杂句后，若字数超限，下一轮只收到字数错误，容易破坏此前修复。使用同一选词的受限诊断请求复现了「质量反馈 → 修订字数超限」这一过程。Cloudflare 和原服务端处理器改为去重保留历轮反馈，提示词明确要求保持已修复约束，并给短文提供符合既有字数和句型要求的段落计划。没有放宽质量校验、切换模型或增加重试次数。

新增 D1 回归测试覆盖「审核失败 → 结构失败 → 第三稿成功」，确认第三次生成同时携带两个阶段的反馈。该测试修复前失败，修复后 Cloudflare API 全部 8 个文件、38 项测试通过，API 类型检查通过。

全工作区 `npm run check` 通过：客户端 386 项、服务端 292 项、契约 33 项，共 711 项；类型检查及 lint 无错误，保留已有 24 条 lint 警告。此前仅在 Node 运行或把 provider 整体替换为 mock 的测试无法发现原生网络函数的接收者限制，新增运行时测试补齐了这个验证范围。
